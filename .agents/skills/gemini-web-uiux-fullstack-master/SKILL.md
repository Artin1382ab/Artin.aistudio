## Systematic end-to-end workflow
1. Intake: establish user goals, audience, page routes, file/repository inputs, brand and exact no-change constraints.
2. Baseline: inspect actual code and runtime; collect before screenshots, errors, console/network data, performance and accessibility results where available.
3. Architecture: choose minimal-change solution, semantic HTML, suitable stack and token design; note security and SEO implications.
4. UI/UX: apply typographic scale, spacing rhythm, state behavior, responsive layouts, meaningful motion, RTL support and keyboard affordances.
5. Implementation: update in small reversible units; never overwrite other components or alter links/brands without permission.
6. Testing: run framework-specific lint/build/type/test, Playwright E2E, accessibility checks and visual regression if connected. Never invent pass/fail results.
7. Delivery: list changes, filenames, verified screenshots, performed commands, untested points, rollback and migration guidance.
